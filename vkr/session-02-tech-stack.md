Все технологии были отобраны с учётом специфики проекта: необходимости поддержки сложных многошаговых сценариев взаимодействия (создание объявлений, прохождение сделки, оплата), высокой интерактивности интерфейса (чат, уведомления, фильтрация каталога в реальном времени), а также требований к адаптивности, доступности и визуальной согласованности.

## 2.2. Обоснование выбора технологий

Выбор технологического стека клиентской части приложения «Арендай» обусловлен спецификой предметной области — платформы аренды вещей между частными лицами, — а также архитектурными требованиями к системе: множество ролей пользователей (гость, арендатор, арендодатель, модератор, администратор), сложные многошаговые сценарии взаимодействия (создание объявления из 4 шагов, прохождение сделки с 7 статусами, оплата с механизмом периодического опроса), необходимость адаптивного отображения на различных устройствах, а также обмена данными в реальном времени в модуле чата. Ниже представлено развёрнутое обоснование выбора каждой ключевой технологии.

### 2.2.1. TypeScript

**Выбор:** TypeScript (версия ^5) вместо JavaScript.

**Обоснование.** Платформа «Арендай» оперирует значительным количеством сложных предметных сущностей: объявления с 6 состояниями жизненного цикла (черновик, модерация, активно, отклонено, архив, удалено), сделки с 7 статусами (ожидает подтверждения, подтверждена, ожидает оплаты, активна, завершена, отклонена, отменена), транзакции с 6 статусами (ожидание, заморожена, списана, возвращена, ошибка, отменена), жалобы с 4 состояниями. Каждая сущность обладает множеством полей, связей и бизнес-правил. В отсутствие строгой типизации высока вероятность ошибок при передаче данных между компонентами, преобразовании серверных ответов в типы интерфейсного слоя, вычислении производных состояний (например, определение доступных кнопок действий по комбинации статуса сделки и роли пользователя).

TypeScript решает эту задачу посредством статического анализа типов на этапе компиляции. В проекте насчитывается 118 файлов с расширением .ts (типы, утилиты, хуки, вспомогательные функции, тесты) и 139 файлов с расширением .tsx (React-компоненты). Каждый функциональный модуль содержит собственный файл описания типов, определяющий типы, специфичные для данного модуля. Типы сущностей предметной области импортируются из бизнес-слоя (`src/business/types/entity/`), что обеспечивает единый контракт данных между слоями приложения.

**Рассмотренные альтернативы.** Использование чистого JavaScript не обеспечивало бы необходимого уровня надёжности при работе с 15 функциональными модулями, 17 общими компонентами, 5 пользовательскими хуками и порядка 25 хуками функциональных модулей. Ошибки в типах данных выявлялись бы только на этапе выполнения, что неприемлемо для платформы, обрабатывающей финансовые операции (модуль оплаты, интеграция с платёжным шлюзом ЮKassa). Flow — альтернативная система типов — не получила сопоставимой экосистемной поддержки и не интегрирована с Next.js.

### 2.2.2. React

**Выбор:** React (версия 19.2.4) в качестве основной библиотеки построения пользовательского интерфейса.

**Обоснование.** React реализует компонентный подход к построению интерфейсов, при котором каждый элемент страницы представлен самодостаточным, переиспользуемым компонентом с собственным состоянием, стилями и логикой. Данная парадигма оптимально соответствует архитектуре платформы «Арендай», где одни и те же элементы интерфейса используются в различных контекстах: компонент каталожной карточки отображает карточку объявления как в каталоге, так и в результатах поиска и в списке избранного; компонент вкладок с обобщённой типизацией применяется в панели администратора (8 вкладок), панели модератора (4 вкладки), личном кабинете, настройках и других модулях.

React 19 предоставляет расширенный набор хуков, на основе которых построены все 5 пользовательских хуков (управление пагинацией, сортировкой, бесконечной прокруткой, перехватом фокуса, прокруткой вверх) и порядка 25 хуков функциональных модулей проекта. Система контекстов React используется для реализации глобальной темизации с поддержкой светлого и тёмного режимов отображения.

**Преимущества для платформы аренды вещей:**

- компонентная переиспользуемость — минимизация дублирования кода при реализации схожих интерфейсов для разных ролей (арендатор и арендодатель видят одну страницу детализации сделки, но с разными кнопками действий);
- декларативный подход к описанию интерфейса — предсказуемость отрисовки при сложных переходах между состояниями (7 статусов сделки × 2 режима просмотра = 14 вариаций интерфейса);
- обширная экосистема — доступность специализированных библиотек для анимаций (Framer Motion), форм (React Hook Form), тестирования (библиотека тестирования);
- поддержка серверной отрисовки через Next.js — важно для индексации каталога объявлений поисковыми системами.

**Рассмотренные альтернативы.** Vue.js 3 — альтернативный фреймворк с аналогичной компонентной моделью, однако обладающий менее развитой экосистемой типизации с TypeScript и меньшим выбором специализированных библиотек (аналоги Framer Motion и библиотеки тестирования менее зрелы). Angular — полноценный фреймворк с встроенным контейнером внедрения зависимостей, валидацией форм и HTTP-клиентом, однако его избыточная абстрактность и более крутая кривая освоения неоправданны для проекта, где бизнес-логика вынесена в отдельный бизнес-слой. Svelte — компилируемый фреймворк с отсутствием виртуальной объектной модели документа, однако его экосистема значительно уступает React по количеству доступных библиотек и интеграций.

### 2.2.3. Next.js

**Выбор:** Next.js (версия 16.2.2) в качестве мета-фреймворка для React-приложения.

**Обоснование.** Next.js предоставляет инфраструктуру для серверной отрисовки, статической генерации, файловой маршрутизации и оптимизации производительности, что критично для платформы аренды. Каталог объявлений, являющийся точкой входа большинства пользователей, требует серверной отрисовки для обеспечения индексации поисковыми системами и быстрого отображения контента при первом посещении.

В проекте используется современная файловая маршрутизация Next.js, при которой каждый маршрут определяется структурой каталогов. Реализовано 17 маршрутов, включая:

- статические маршруты: каталог, панель администратора, мессенджер, личный кабинет и другие;
- динамические маршруты: карточка объявления по идентификатору, публичный профиль пользователя по идентификатору;
- вложенные динамические маршруты: редактирование объявления по идентификатору.

Next.js также обеспечивает встроенную поддержку модульных стилей CSS (автоматическая генерация уникальных имён классов), оптимизацию изображений, компонент обработки ошибок на уровне маршрутов и разделение серверного и клиентского кода.

**Преимущества для платформы аренды вещей:**

- оптимизация для поисковых систем — объявления индексируются поисковыми роботами, что увеличивает органический трафик;
- быстрая первоначальная загрузка — критично для мобильных пользователей, составляющих значительную долю аудитории платформ аренды;
- файловая маршрутизация — интуитивная организация 17 маршрутов с поддержкой динамических параметров (идентификатор объявления, идентификатор пользователя, идентификатор сделки);
- разделение серверного и клиентского кода — бизнес-слой отрисовывает серверные страницы, слой интерфейса использует клиентские компоненты.

**Рассмотренные альтернативы.** Связка Vite и React Router — без серверной отрисовки из коробки, требующая дополнительной настройки. Remix — альтернативный мета-фреймворк для React с фокусом на серверных формах и прогрессивном улучшении, однако на момент начала разработки обладавший менее зрелой экосистемой и меньшим сообществом. Gatsby — генератор статических сайтов, оптимальный для контентных ресурсов, но неприменимый для динамической платформы с функциональностью обмена данными в реальном времени (чат, уведомления, периодический опрос статуса платежей).

### 2.2.4. SCSS и модульные стили CSS

**Выбор:** Sass (SCSS, версия ^1.98.0) в сочетании с модульными стилями CSS вместо библиотек стилей на основе JavaScript или атомарных CSS-фреймворков.

**Обоснование.** Архитектура стилей платформы «Арендай» построена на принципе дизайн-токенов — централизованных переменных, определяющих визуальный язык приложения. Файл переменных содержит полный набор токенов: палитру цветов (основной, акцентный, текстовый, фоновый), типографическую шкалу (гарнитуры Inter, Plus Jakarta Sans, JetBrains Mono), систему отступов (от 4 до 96 пикселей с шагом 4 пикселя), радиусы скругления, тени различной интенсивности (малая, средняя, большая, очень большая, а также специальные: премиальная, карточная, стеклянная, зелёное свечение), точки адаптивных переходов (480, 640, 768, 1024, 1280, 1536 пикселей) и шкалу приоритетов наложения.

SCSS обеспечивает возможности, недоступные в чистом CSS: вложенные селекторы для лаконичного описания иерархических стилей, миксины для переиспользуемых шаблонов стилей (адаптивные переходы, центрирование, стеклянная карточка, мерцающая анимация загрузки — всего более 20 миксинов), функции для вычислений, а также модульную организацию через директиву подключения. В проекте — 132 файла стилей, включая 12 файлов адаптивных стилей для отдельных функциональных модулей.

Модульные стили CSS, встроенные в Next.js, обеспечивают изоляцию стилей на уровне компонента: каждый файл стилей с суффиксом `.module.scss` генерирует уникальные хешированные имена классов, что исключает коллизии стилей между модулями. Это особенно важно при параллельной разработке 15 функциональных модулей несколькими разработчиками.

**Рассмотренные альтернативы.** Библиотеки стилей на основе JavaScript (Styled Components, Emotion) — подход, при котором стили описываются непосредственно в коде JavaScript, что размывает границу между логикой и представлением. Для проекта с 132 файлами стилей и разветвлённой дизайн-системой данный подход привнёс бы избыточные вычислительные затраты на этапе выполнения. Tailwind CSS — атомарный CSS-фреймворк, оптимальный для прототипирования, однако его утилитарные классы загромождают JSX-разметку при построении сложных компонентов (эффекты размытия, многоуровневые градиенты, условные стили по 7 статусам сделки). В проекте Tailwind CSS присутствует как зависимость, однако основная стилизация выполнена средствами SCSS и модульных стилей, что обеспечивает более выразительный и структурированный подход.

### 2.2.5. Framer Motion

**Выбор:** Framer Motion (версия ^12.38.0) в качестве библиотеки анимаций.

**Обоснование.** Пользовательский интерфейс платформы аренды включает множество динамических переходов, требующих плавной анимации: переключение вкладок в личном кабинете и панелях администратора и модератора, появление и скрытие модальных окон (окно «Поделиться», окно жалобы на объявление, окно жалобы на пользователя, окно авторизации, окно поиска), смена содержимого карточки сделки при изменении статуса (7 статусов × 2 роли), анимация главной секции гостевой страницы, плавное отображение каталожных карточек при загрузке.

Framer Motion реализует декларативный подход к анимациям через специализированные React-компоненты и контейнер управления жизненным циклом анимации, что позволяет описывать анимации непосредственно в разметке без императивного управления объектной моделью документа. В проекте библиотека применяется в следующих модулях:

- страница детализации сделки — анимация переключения между 10 демонстрационными сценариями;
- гостевая страница — анимация появления баннера и карточек каталога;
- карточка товара — анимация галереи изображений;
- личный кабинет — анимация переходов между вкладками.

Единая кривая анимации (кубическая кривая Безье), определённая в файле констант, обеспечивает визуальную согласованность анимаций во всех модулях.

**Рассмотренные альтернативы.** React Spring — библиотека анимаций на основе физических моделей (пружинные модели), обладающая более низкоуровневым программным интерфейсом и менее интуитивным синтаксисом для типовых задач (плавное появление и исчезновение, скольжение). Нативные CSS-анимации (ключевые кадры и переходы) — встроенный подход, однако не обеспечивающий управление анимациями при монтировании и демонтировании компонентов без дополнительного кода. GSAP — мощная библиотека анимаций, ориентированная на императивный стиль, что противоречит декларативной модели React.

### 2.2.6. React Hook Form и Zod

**Выбор:** React Hook Form (версия ^7.72.0) с адаптером @hookform/resolvers (версия ^5.2.2) и схемами валидации Zod (версия ^4.3.6).

**Обоснование.** Платформа «Арендай» содержит множество интерактивных форм с различными требованиями к валидации:

- форма регистрации — 4 поля: имя, телефон с маской +7, пароль, подтверждение пароля;
- форма авторизации — 3 поля: телефон, пароль, флажок «Запомнить меня»;
- создание объявления — 4-шаговый мастер с полями: категория, заголовок, описание, характеристики, город, место передачи, цена, залог, фотографии;
- настройки профиля — 5 секций с полями различных типов.

React Hook Form построен на принципе неконтролируемых компонентов, что минимизирует количество повторных отрисовок при вводе данных — это критично для многопольных форм с мгновенной валидацией. Библиотека Zod описывает схемы валидации в декларативном стиле с полной типобезопасностью TypeScript: типы форм выводятся автоматически из схемы, исключая рассогласование между описанием валидации и типами полей.

Интеграция осуществляется через адаптер @hookform/resolvers, который связывает схему Zod с React Hook Form, обеспечивая автоматическую валидацию при каждом событии ввода и отображение локализованных сообщений об ошибках.

**Рассмотренные альтернативы.** Formik — популярная библиотека форм для React, однако использующая контролируемые компоненты, что приводит к избыточным отрисовкам в формах с большим количеством полей. Formik также не обладает встроенной интеграцией с типизированными схемами. Yup — библиотека валидации, совместимая с Formik, однако уступающая Zod в строгости типизации и декларативности синтаксиса.

### 2.2.7. Vitest и библиотека тестирования

**Выбор:** Vitest (версия ^4.1.6) в сочетании с @testing-library/react (версия ^16.3.2), @testing-library/jest-dom (версия ^6.9.1), @testing-library/user-event (версия ^14.6.1) и jsdom (версия ^29.1.1).

**Обоснование.** Тестирование пользовательского интерфейса платформы аренды охватывает следующие области: утилитарные функции форматирования (форматирование цен, дат, времени, русская плюрализация), преобразователи данных (преобразование серверных объектов передачи данных в модели интерфейса), вспомогательные функции функциональных модулей (фильтрация каталога, вычисление заполненности профиля, публичные профили), React-компоненты (вкладки, обработчик ошибок) и пользовательские хуки (пагинация, сортировка). Всего реализовано 176 тестов в 10 тестовых файлах с результатом 0 ошибок.

Vitest выбран как нативно совместимый с экосистемой Vite и TypeScript фреймворк тестирования. Он обеспечивает:

- мгновенный запуск тестов за счёт модульной архитектуры на основе стандарта ECMAScript;
- встроенную поддержку TypeScript без дополнительной конфигурации;
- совместимость с программным интерфейсом Jest, что снижает порог освоения;
- поддержку модульных стилей CSS — необходимо для тестирования компонентов, использующих SCSS-модули;
- режим наблюдения за файлами для итеративной разработки и однократный прогон с отчётом о покрытии кода.

Библиотека тестирования реализует философию «тестирования с перспективы пользователя»: компоненты тестируются через их внешнее поведение (текст, роли, атрибуты), а не через внутреннюю реализацию. Это обеспечивает устойчивость тестов при рефакторинге компонентов.

**Рассмотренные альтернативы.** Jest — стандартный фреймворк тестирования для React-проектов, однако требующий дополнительной конфигурации для поддержки TypeScript, модулей стандарта ECMAScript и модульных стилей CSS. Для проекта на Next.js фреймворк Vitest является нативной альтернативой с минимальной дополнительной конфигурацией. Cypress и Playwright — инструменты сквозного тестирования, тестирующие приложение через реальный браузер. Они дополняют (но не заменяют) модульные тесты и предназначены для тестирования полных пользовательских сценариев на интеграционном уровне. Enzyme — устаревшая библиотека тестирования React-компонентов, не поддерживающая React 19 и стимулирующая тестирование внутренней реализации компонентов.

Heroicons — набор иконок от команды Tailwind CSS, оптимальный для проектов на Tailwind, но с меньшим количеством доступных иконок по сравнению с Lucide.

Шаблонные строковые литералы — нативный подход, однако становящийся нечитаемым при трёх и более условных классах, что характерно для компонентов данной платформы.

### 2.2.11. Redux Toolkit и React Redux

**Выбор:** @reduxjs/toolkit (версия ^2.11.2) и React Redux (версия ^9.2.0) для управления глобальным состоянием и серверным кешированием.

**Обоснование.** Хотя Redux Toolkit находится в зоне ответственности бизнес-слоя (`src/business/`), слой интерфейса является его непосредственным потребителем. Все интерактивные действия пользователя — создание заявки на аренду, подтверждение или отклонение сделки, оплата, запуск и завершение аренды — реализованы через мутации и запросы подсистемы серверного кеширования, которые компоненты интерфейса вызывают через импортируемые хуки бизнес-слоя.

Подсистема серверного кеширования Redux Toolkit обеспечивает:

- автоматическое кеширование серверных данных;
- механизм периодического опроса (интервал 5 секунд в модуле оплаты для отслеживания статуса транзакции ЮKassa);
- управление состояниями загрузки (выполняется, завершено успешно, завершено с ошибкой) для отображения каркасных экранов и сообщений об ошибках;
- инвалидацию кеша при мутациях (обновление списка сделок после подтверждения).

**Рассмотренные альтернативы.** TanStack Query (React Query) — альтернативная библиотека серверного кеширования, однако в контексте проекта, где бизнес-слой уже построен на Redux Toolkit, использование отдельной библиотеки для кеширования привело бы к дублированию инфраструктуры. Zustand — минималистичная библиотека состояния, не предоставляющая встроенного механизма серверного кеширования и периодического опроса. MobX — библиотека реактивного состояния на основе наблюдателей, концептуально отличающаяся от предсказуемой модели Redux и менее совместимая с серверной отрисовкой Next.js.
