## 1. Модуль «Каталог» (58 файлов)

### 1.1. Назначение

Модуль «Каталог» является крупнейшим функциональным модулем слоя представления и реализует основную клиентскую функцию платформы «Арендай» — поиск, фильтрацию и просмотр объявлений об аренде вещей. Модуль обеспечивает выполнение четырёх пользовательских сценариев: «Поиск и фильтрация объявлений» (сценарий 4), «Просмотр карточки объявления» (сценарий 7), «Отправка запроса на аренду» (сценарий 9) и «Подача жалобы» (сценарий 18, в части жалобы на объявление).

### 1.2. Внутренняя структура

Модуль содержит два корневых компонента, четыре подкаталога компонентов, каталог стилей, каталог тестов и вспомогательные файлы.

**Корневые компоненты:**
- Главная страница каталога (9 083 байт) — отображает приветственную секцию, горизонтальную ленту категорий, сетку карточек объявлений с бесконечной прокруткой и панель фильтров.
- Страница результатов поиска (6 254 байт) — отображает результаты текстового поиска с фильтрами, сортировкой и навигационной цепочкой.

**Подкаталоги компонентов (38 файлов):**

**Таблица 9 — Структура компонентов модуля «Каталог»**

| Подкаталог | Файлов | Компоненты |
|---|---|---|
| Карточки | 10 | Карточка объявления (изображение, цена, рейтинг, город, залог), скелетонная карточка |
| Детальный просмотр | 10 | Детальная страница объявления, галерея изображений, боковая панель бронирования, календарь аренды, модальное окно жалобы на объявление |
| Фильтры | 16 | Панель фильтров, строка поиска, панель инструментов, горизонтальная лента категорий, стилизованный выпадающий список, вложенный каталог стилей фильтров |
| Раскладка | 2 | Компоненты-обёртки для адаптивного размещения каталога |

**Перехватчики (1 файл):** перехватчик каталога, управляющий состоянием фильтров, загрузкой данных и бесконечной прокруткой.

**Стили (8 файлов):** базовые стили, сетка и карточки, детальный просмотр и бронирование, шапка, приветственная секция и категории, адаптивные стили, поиск и фильтры, состояния и скелетоны.

### 1.3. Система типов

Файл типов (47 строк, 1 228 байт) определяет:
- Тип элемента каталога — расширяет серверную модель представления (импортируемую из бизнес-слоя) дополнительными полями: категория, данные владельца (идентификатор, имя, аватар, рейтинг, число отзывов), массив изображений, описание, город, условия аренды, технические характеристики.
- Тип ключа сортировки — 5 вариантов: по популярности, по цене (возрастание), по цене (убывание), по новизне, по рейтингу.
- Тип состояния фильтров — 9 полей: текстовый поиск, город, категория, минимальная и максимальная цена, флаг доступности, ключ сортировки, быстрый фильтр, наличие залога.

### 1.4. Модуль преобразования данных

Файл преобразователей (36 строк, 1 323 байт) содержит две функции:
- Функция преобразования единичной серверной модели представления в клиентский тип элемента каталога — заполняет недостающие поля (данные владельца, массив изображений, категория) значениями по умолчанию или из переданного объекта дополнительных данных.
- Пакетная функция преобразования массива серверных моделей — применяет единичное преобразование к каждому элементу с возможностью передачи дополнительных данных по индексу.

Обе функции покрыты 8 модульными тестами.

### 1.5. Утилиты каталога

Файл утилит (7 691 байт) содержит функции фильтрации и сортировки элементов каталога, параметры категорий, функции преобразования фильтров в параметры строки запроса и обратно, функцию генерации текстовой сводки активных фильтров. Покрыт 43 модульными тестами.

### 1.6. Интеграция боковой панели бронирования с бизнес-слоем

Компонент боковой панели бронирования (раздел 6.22) интегрирован с серверной частью для создания заявки на аренду. Процесс взаимодействия:

1. Пользователь выбирает даты в компоненте календаря аренды.
2. Боковая панель вычисляет стоимость (цена × количество дней).
3. При нажатии кнопки «Отправить запрос» вызывается мутация бизнес-слоя для создания заявки.
4. В процессе загрузки кнопка отображает текст «Отправка...» и блокируется.
5. При успешном создании заявки осуществляется программная навигация на страницу деталей сделки с идентификатором созданной заявки.
6. При ошибке — навигация на страницу деталей сделки в демонстрационном режиме.
7. Для неавторизованных пользователей — вызов обратной функции отображения модального окна авторизации.

Параметры запроса: идентификатор объявления, даты начала и окончания в формате стандарта, режим ценообразования (посуточный или почасовой).

### 1.7. Тестовое покрытие

Каталог тестов содержит 2 файла с суммарным покрытием 51 тест: 43 теста утилит (фильтрация, сортировка, форматирование, преобразование параметров) и 8 тестов преобразователей данных.

### 1.8. Демонстрационные данные

Файл демонстрационных данных (26 647 байт) содержит набор реалистичных объявлений со всеми необходимыми полями для автономной работы модуля в режиме разработки. Файл справочника городов (285 540 байт) содержит полный перечень населённых пунктов Российской Федерации для компонента выбора города.

## 2. Модуль «Создание объявления» (19 файлов)

### 2.1. Назначение

Модуль реализует пользовательский сценарий 5 «Создание объявления на аренду» в формате четырёхшагового мастера (пошагового руководства). Каждый шаг является отдельным компонентом, а корневой компонент управляет текущим шагом и состоянием формы.

### 2.2. Внутренняя структура

**Корневой компонент** (10 098 байт) — управляет навигацией между четырьмя шагами, хранит объединённое состояние формы и отображает индикатор прогресса.

**Компоненты шагов (7 файлов):**
- Шаг 1 «Фотографии» — загрузка изображений, создание предпросмотра из локальных файлов, перетаскивание для изменения порядка.
- Шаг 2 «Информация» — название, категория, состояние вещи (новая, как новая, хорошее, б/у), описание, технические характеристики (динамический набор в зависимости от категории).
- Шаг 3 «Ценообразование» — цена за сутки, цена за час, размер залога (с возможностью отключения), город, место передачи.
- Шаг 4 «Предварительный просмотр» — отображение заполненных данных в формате карточки объявления для проверки перед отправкой.
- Компонент выбора города — выпадающий список с поиском по справочнику городов.
- Компонент выбора характеристик — динамическое добавление пар «свойство — значение» для выбранной категории.

**Перехватчик** (1 файл) — управляет состоянием формы, валидацией на каждом шаге и отправкой данных.

**Стили** (6 файлов) — базовые стили, стили формы, стили шагов, стили предпросмотра, стили загрузки фотографий, адаптивные стили.

### 2.3. Система типов

Файл типов (35 строк, 748 байт) определяет:
- Тип состояния вещи — 4 варианта: новая, как новая, хорошее состояние, бывшая в употреблении.
- Тип предпросмотра изображения — идентификатор и ссылка на локальный файл.
- Тип записи характеристики — пара «подпись — значение».
- Тип данных формы создания объявления — 13 полей: название, категория, состояние, описание, массив изображений, массив характеристик, город, цена за сутки, цена за час, размер залога, флаг «без залога», место передачи.

### 2.4. Справочник категорийных характеристик

Файл справочника (4 759 байт) определяет наборы характеристик для каждой категории объявлений. При выборе категории на шаге 2 компонент выбора характеристик автоматически предлагает соответствующие поля (например, для категории «Электроника» — диагональ, память, ёмкость батареи).

## 3. Модуль «Чат» (17 файлов)

### 3.1. Назначение

Модуль реализует пользовательский сценарий 13 «Обмен сообщениями в чате» и обеспечивает коммуникацию между арендатором и арендодателем в рамках конкретного объявления или сделки.

### 3.2. Внутренняя структура

**Корневой компонент** (3 701 байт) — разделяет экран на две зоны: список диалогов (боковая панель) и текущий диалог (основная область).

**Компоненты (6 файлов):**
- Список диалогов — фильтрация по вкладкам (все, сдаю, арендую, запросы), поиск, аватары с индикаторами присутствия и набора текста.
- Заголовок диалога — имя собеседника, статус сделки, ссылка на объявление.
- Контекстная панель сделки — отображение текущего статуса сделки, цены, дат и залога.
- Лента сообщений — хронологически упорядоченная лента с разделителями дат, текстовыми сообщениями и системными событиями.
- Пузырь сообщения — стилизация входящих и исходящих сообщений с временной меткой и индикатором прочтения.
- Панель быстрых действий — контекстные кнопки управления сделкой (подтвердить, отклонить, оплатить) в зависимости от статуса.

**Перехватчик** (1 файл) — управляет текущим диалогом, загрузкой сообщений и отправкой.

**Стили** (5 файлов) — базовые, список диалогов, лента сообщений, контекстная панель, адаптивные.

### 3.3. Система типов

Файл типов (98 строк, 2 771 байт) определяет 9 типов и интерфейсов:

- Тип вкладки списка диалогов — 4 варианта: все, сдаваемые, арендуемые, запросы.
- Тип предпросмотра диалога — расширяет серверный тип данными собеседника (имя, аватар, присутствие, набор текста), контекстом объявления (название, изображение), контекстом сделки (статус, цена, даты, залог), ролью текущего пользователя, счётчиком непрочитанных, флагами закрепления и архивации.
- Тип сообщения — расширяет серверный тип флагом принадлежности текущему пользователю, временем прочтения, опциональным вложением изображения.
- Тип системного события — 12 видов событий жизненного цикла сделки (создание, подтверждение, ожидание оплаты, оплата, подтверждение старта, активация, подтверждение возврата, завершение, отклонение, отмена, досрочное завершение, оставление отзыва).
- Тип быстрого действия — подпись, вариант оформления (основной, вторичный, опасный), иконка, флаг и подсказка блокировки.
- Тип записи ленты — объединение трёх видов: сообщение, системное событие, разделитель даты.

### 3.4. Демонстрационные данные

Файл демонстрационных данных (36 704 байт) содержит полный набор тестовых диалогов, сообщений, системных событий и быстрых действий для автономной работы модуля.

## 4. Модуль «Детали сделки» (14 файлов)

### 4.1. Назначение

Модуль реализует визуализацию полного жизненного цикла сделки аренды и обеспечивает выполнение пользовательских сценариев 12 «Подтверждение или отмена аренды», 15 «Отслеживание статуса сделки» и 16 «Подтверждение возврата вещи».

### 4.2. Внутренняя структура

**Корневой компонент** (3 802 байт, 122 строки) — отображает карточку сделки с анимированными переходами между состояниями. В демонстрационном режиме предоставляет переключатель 10 сценариев, покрывающих все комбинации статусов и ролей.

**Компоненты (6 файлов):**
- Изображение вещи — фотография с градиентным наложением и индикатором статуса в виде пилюли.
- Пошаговый индикатор прогресса — вертикальный 5-шаговый индикатор с градиентными линиями, светящимися кругами и описаниями каждого этапа.
- Условия сделки — период аренды, стоимость, размер залога, город, место передачи; разделители между строками выполнены пунктиром.
- Карточка участника — аватар с инициалами, имя, роль (арендатор или арендодатель), иконка перехода к профилю.
- Блок причины — условно отображаемый блок с текстом причины отклонения или отмены; отображается только для статусов «Отклонена» и «Отменена».
- Кнопки действий — контекстные кнопки, набор которых определяется комбинацией статуса сделки и роли текущего пользователя.

### 4.3. Вспомогательные функции

Файл вспомогательных функций (5 819 байт, 160 строк) содержит бизнес-логику слоя представления:

- Функция генерации шагов индикатора прогресса — сопоставляет каждый статус сделки с номером активного шага из пяти (заявка, подтверждение, оплата, передача вещи, завершение). Для конечных статусов («Отклонена», «Отменена») прогресс фиксируется на соответствующем шаге.
- Функция получения контекстного сообщения — возвращает русскоязычное описание текущего состояния сделки с учётом роли пользователя (7 статусов × 2 роли = 14 уникальных сообщений).
- Функция определения набора кнопок — формирует массив доступных действий в зависимости от статуса и роли.
- Функции форматирования даты и суммы, определения цвета индикатора статуса.

### 4.4. Связь с бизнес-слоем

Кнопки действий сопоставлены с перехватчиками бизнес-слоя: подтверждение заявки, отклонение заявки, отмена сделки, подтверждение старта, подтверждение завершения. Кнопка «Оплатить» осуществляет навигацию на страницу модуля оплаты. Кнопка «Оставить отзыв» — навигацию на страницу отзывов.

### 4.5. Стилистическое оформление

Базовый файл стилей (530 строк) реализует стилизацию в стиле стекломорфизма: полупрозрачная закреплённая шапка с размытием фона, трёхцветный градиентный фон страницы, карточка с увеличенным скруглением и многослойной тенью, изображение с градиентным наложением и увеличением при наведении, индикатор прогресса со светящимися кругами и градиентными линиями, кнопки с тенью зелёного свечения и эффектом подъёма при наведении.

## 5. Модуль «Оплата» (13 файлов)

### 5.1. Назначение

Модуль реализует пользовательский сценарий 10 «Внесение арендной платы» и обеспечивает визуализацию процесса оплаты аренды через платёжную систему ЮКасса.

### 5.2. Внутренняя структура

**Корневой компонент** (5 058 байт) — отображает статус платежа, сводку стоимости и кнопки действий. В демонстрационном режиме предоставляет переключатель всех 7 визуальных состояний.

**Компоненты (4 файла):**
- Карточка статуса платежа — отображает иконку, цветовой индикатор, текстовое описание текущего состояния платежа.
- Сводка стоимости — детализация суммы: стоимость аренды, залог, сервисный сбор (10%), итого.
- Кнопки действий — контекстные кнопки (оплатить, повторить попытку, вернуться) в зависимости от состояния платежа.
- Скелетонный экран — макет страницы с мерцающими блоками для индикации загрузки.

### 5.3. Перехватчик потока оплаты (77 строк)

Перехватчик является центральным элементом модуля и реализует интеграцию с бизнес-слоем:

- Получение данных платежа — использует запрос бизнес-слоя для получения текущего состояния платежа по идентификатору сделки.
- Создание платежа — использует мутацию бизнес-слоя для создания нового платежа.
- Отмена платежа — использует мутацию бизнес-слоя для отмены платежа.
- Периодический опрос — при нахождении платежа в промежуточных состояниях («Ожидает» или «Заморожена») перехватчик запускает периодический опрос с интервалом 5 секунд для обнаружения перехода в конечное состояние. При переходе в конечное состояние опрос автоматически останавливается.
- Перенаправление на оплату — функция открывает ссылку подтверждения платежа (полученную от серверной части) в новом окне браузера.

Перехватчик возвращает 7 значений: данные платежа, визуальное состояние, флаг загрузки, функции создания и отмены платежа, функцию обновления данных и функцию перенаправления на оплату.
