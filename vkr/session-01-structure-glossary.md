## 6.13. Рекомендуемая структура отчёта по выпускной квалификационной работе

Тема ВКР: «Разработка клиентской части веб-приложения P2P-платформы аренды вещей "Арендай"».

Ниже приведена рекомендуемая структура отчёта с указанием содержимого каждого раздела применительно к выполненной работе.

---

### Введение

Во введении раскрываются следующие аспекты:

**Актуальность темы.** Рынок совместного потребления (sharing economy) демонстрирует устойчивый рост: по данным аналитических агентств, объём P2P-аренды в сегменте вещей ежегодно увеличивается на 15–25 %. Существующие решения, такие как Avito и Rentmania, либо не специализируются на аренде (являясь универсальными классифайдами), либо имеют ограниченное UX-качество и не предоставляют полного жизненного цикла сделки — от создания объявления до взаимного оценивания сторон. Разработка специализированной платформы «Арендай» направлена на устранение данного пробела путём создания удобного, функционального и надёжного пользовательского интерфейса.

**Цель работы.** Разработка клиентской части (UI/UX-слоя) веб-приложения P2P-платформы аренды вещей «Арендай», обеспечивающей полный пользовательский путь для четырёх категорий акторов: гость, клиент (арендатор/арендодатель), модератор и администратор.

**Задачи работы:**
1. Провести анализ предметной области и существующих аналогов P2P-платформ аренды.
2. Определить и обосновать технологический стек клиентской части.
3. Спроектировать архитектуру UI-слоя на основе модульного подхода Feature-Sliced Design.
4. Разработать дизайн-систему: палитру цветов, типографику, сетку отступов, компоненты-примитивы.
5. Реализовать 15 фича-модулей, покрывающих 18 клиентских сценариев, 8 сценариев модератора и 9 сценариев администратора.
6. Реализовать 17 shared UI-компонентов и 4 layout-модуля.
7. Обеспечить адаптивность интерфейса для различных устройств.
8. Обеспечить доступность интерфейса (accessibility): клавиатурная навигация, aria-атрибуты, skip-links.
9. Провести модульное тестирование UI-утилит, маппёров, хелперов, компонентов и хуков (176 тестов).
10. Интегрировать UI-слой с бизнес-слоем приложения через типизированный API (импорт типов и хуков).

**Объект исследования** — процесс разработки пользовательского интерфейса P2P-платформы аренды вещей.

**Предмет исследования** — методы и средства проектирования и реализации клиентской части веб-приложения с применением модульной архитектуры, дизайн-системы и современного технологического стека.

**Практическая значимость.** Результатом работы является готовый к интеграции UI-слой платформы «Арендай», включающий 394 файла (~64 500 строк кода), 15 фича-модулей, 17 маршрутов и 176 автоматизированных тестов, покрывающий все 35 документированных сценариев использования.

1. Интуитивность — минимизация времени освоения, знакомые паттерны.

3. Производительность (с точки зрения пользователя) — минимизация кликов и навигационных переходов.
4. Обратная связь — уведомления о статусах, ошибки валидации, изменение состояний сделок.

Принцип разделения ответственности: `src/ux/` (UI-слой, зона ответственности автора) зависит от `src/business/` (бизнес-слой, зона ответственности другого разработчика) исключительно через импорт типов и хуков. Описание паттернов: Component-driven development, Barrel exports, Mock-driven development, Skeleton screens, Error Boundary, Infinite scroll, Keyboard navigation.

Из проекта: 15 фича-модулей, 17 shared UI-компонентов, 5 кастомных хуков, 4 layout-модуля.

Показана зависимость от `src/business/` (типы и хуки). Выделены shared-компоненты, используемые в нескольких фичах (AdminPagination, AdminSelect, SortableHeader, TableSkeleton, Tabs, AppInput, EmptyState и др.).

Содержание: семь UML Activity Diagrams:

2. Процесс аренды (поиск → бронирование → оплата → старт → завершение).

Содержание: UML Deployment Diagram. Клиент (браузер) → Next.js (SSR/CSR) → REST API → база данных. Внешние сервисы: ЮKassa (платёжный шлюз), Amazon S3 (хранение фотографий), Socket.IO (real-time чат).

#### 2.8. Диаграммы последовательности

Содержание: шесть UML Sequence Diagrams:
1. Сценарий оплаты: Пользователь → UI → бизнес-хук → API → ЮKassa → callback → обновление статуса.
2. Создание объявления: форма → валидация → загрузка фото (S3) → отправка → модерация.
3. Создание заявки на аренду: BookingSidebar → useCreateDealRequest → POST /deals → router.push.
4. Детальный сценарий оплаты: DealDetailsPage → PaymentPage → usePaymentFlow → GET /payments/deal/{id} (polling 5 с) → PaymentStatusCard → PaymentActions.
5. Подтверждение/отклонение заявки (owner): DealDetailsPage → useConfirmDeal / useRejectDeal → PUT /deals/{id}/confirm|reject.
6. Досрочная отмена (ACTIVE): DealDetailsPage → useCancelDeal → PUT /deals/{id}/cancel → DealReasonBlock.

### Веб-технологии и архитектура

**SPA (Single Page Application)** — одностраничное приложение, в котором навигация между экранами происходит без полной перезагрузки страницы. Весь интерфейс загружается один раз, а последующие переходы обновляют лишь изменившуюся часть DOM-дерева. В проекте «Арендай» SPA-поведение реализовано средствами Next.js App Router.

**SSR (Server-Side Rendering)** — серверный рендеринг, при котором HTML-страница формируется на сервере и передаётся клиенту в готовом виде. Данный подход улучшает индексируемость страниц поисковыми системами (SEO) и ускоряет первичную отрисовку (First Contentful Paint). В проекте SSR обеспечивается фреймворком Next.js 16.

**CSR (Client-Side Rendering)** — клиентский рендеринг, при котором HTML-страница формируется в браузере пользователя посредством выполнения JavaScript-кода. В проекте CSR применяется для интерактивных компонентов, помеченных директивой `'use client'`.

**SSG (Static Site Generation)** — статическая генерация страниц на этапе сборки приложения. Готовые HTML-файлы отдаются из CDN без обращения к серверу. В проекте данный подход применим для информационных страниц (InfoPages).

**REST API (Representational State Transfer Application Programming Interface)** — архитектурный стиль взаимодействия компонентов распределённого приложения по протоколу HTTP. В проекте REST API используется для обмена данными между клиентской частью и серверной частью платформы (CRUD-операции с объявлениями, сделками, пользователями и пр.).

**DTO (Data Transfer Object)** — объект передачи данных, используемый для пересылки структурированных данных между слоями приложения. В проекте DTO определяются на серверной стороне и преобразуются в View Model на бизнес-слое фронтенда.

**View Model** — модель представления, содержащая данные в формате, удобном для отображения в пользовательском интерфейсе. В проекте View Model определяются в `src/business/types/view/` и импортируются UI-слоем.

**WebSocket** — протокол полнодуплексной связи поверх TCP-соединения, обеспечивающий двунаправленный обмен сообщениями в реальном времени между клиентом и сервером. В проекте используется через библиотеку Socket.IO для реализации чата.

### Фреймворки и библиотеки

**React** — JavaScript-библиотека для построения пользовательских интерфейсов, разработанная компанией Meta (ранее Facebook). Основана на концепции компонентного подхода и виртуального DOM. В проекте используется React 19.2.4.

**Next.js** — фреймворк для React-приложений, разработанный компанией Vercel. Обеспечивает серверный рендеринг (SSR), статическую генерацию (SSG), маршрутизацию на основе файловой системы (App Router), оптимизацию изображений и другие возможности «из коробки». В проекте используется Next.js 16.2.2.

**App Router** — архитектурная модель маршрутизации в Next.js, основанная на файловой структуре каталога `src/app/`. Каждый файл `page.tsx` в подкаталоге автоматически становится маршрутом. Поддерживает вложенные layout-компоненты, серверные компоненты, error boundaries и динамические сегменты.

**Redux Toolkit (RTK)** — официальная библиотека для управления глобальным состоянием в React-приложениях. Включает утилиты для создания хранилища (store), слайсов (slice) и асинхронных запросов (RTK Query). В проекте используется RTK 2.11.2 в бизнес-слое; UI-слой взаимодействует с ним через хуки.

**RTK Query** — модуль Redux Toolkit для декларативного управления серверным состоянием: кэширование, автоматическая инвалидация, polling. В проекте применяется для платёжного модуля (usePaymentFlow — polling каждые 5 секунд) и для создания заявок на аренду (useCreateDealRequest).

**Framer Motion** — библиотека декларативных анимаций для React. Предоставляет компоненты `motion`, `AnimatePresence` для анимации появления, исчезновения и перемещения элементов. В проекте используется версия 12.38.0 для анимаций в DealDetailsPage, Guest (hero-секция), ProfileDashboard и других модулях.

**Socket.IO** — библиотека для организации real-time двунаправленной коммуникации между клиентом и сервером. Поддерживает fallback с WebSocket на HTTP long-polling. В проекте используются socket.io 4.8.3 (серверная часть) и socket.io-client 4.8.3 (клиентская часть) для реализации чата.

**Zod** — библиотека валидации схем данных для TypeScript с полной поддержкой статического вывода типов. В проекте используется Zod 4.3.6 совместно с React Hook Form (через @hookform/resolvers 5.2.2) для валидации форм регистрации, входа, создания объявления и настроек профиля.

**React Hook Form** — библиотека для управления формами в React с минимальным количеством повторных рендеров. В проекте используется версия 7.72.0 для форм авторизации (LoginForm, RegisterForm) и создания объявлений (CreateListing).

**Lucide React** — библиотека SVG-иконок для React, являющаяся форком Feather Icons с расширенным набором. В проекте используется версия 1.7.0 для иконографии во всех модулях (навигация, статусы, действия, уведомления).

**clsx** — утилита для условной композиции CSS-классов. Принимает строки, объекты и массивы, возвращая итоговую строку классов. В проекте используется версия 2.1.1 для динамического управления стилями в компонентах.

**next-auth** — библиотека аутентификации для Next.js. Поддерживает множество провайдеров (OAuth, Credentials). В проекте используется версия 5.0.0-beta.30 для управления сессиями и CSRF-защиты.

### Языки программирования и типизация

**TypeScript** — типизированное надмножество JavaScript, разработанное компанией Microsoft. Добавляет статическую типизацию, интерфейсы, дженерики и другие возможности. Компилируется в JavaScript. В проекте используется TypeScript 5.x для строгой типизации всех модулей.

**JSX (JavaScript XML)** — синтаксическое расширение JavaScript, позволяющее описывать структуру UI в виде XML-подобных выражений внутри JavaScript-кода. Используется в React для описания компонентов.

**TSX** — файлы TypeScript, содержащие JSX-выражения. Расширение `.tsx` указывает компилятору TypeScript на необходимость обработки JSX-синтаксиса. В проекте все React-компоненты имеют расширение `.tsx` (139 файлов).

### Стилизация

**SCSS (Sassy CSS)** — препроцессор CSS, расширяющий возможности стандартного CSS переменными, вложенностью селекторов, миксинами, функциями, циклами и импортами. В проекте используется Sass 1.98.0 для стилизации всех модулей (132 файла стилей).

**CSS Modules** — методология изоляции стилей на уровне компонента. Каждый файл `.module.scss` автоматически генерирует уникальные имена классов, исключая глобальные конфликты. В проекте все компонентные стили реализованы как CSS Modules.

**Design Tokens (дизайн-токены)** — именованные константы дизайн-системы (цвета, размеры шрифтов, отступы, тени, breakpoints), хранящиеся централизованно в файле `vars.scss`. Обеспечивают единообразие визуального языка и упрощают внесение изменений.

**SCSS-миксин (mixin)** — переиспользуемый блок SCSS-кода, параметризованный через аргументы. В проекте определено 20+ миксинов в файле `helpers/mixins.scss` (respond-to, flex-center, glass-card, skeleton-shimmer и др.).

**Glassmorphism** — стилистический приём UI-дизайна, использующий полупрозрачные фоны с размытием (backdrop-filter: blur) для создания эффекта «матового стекла». В проекте применяется в DealDetailsPage, Guest, BookingSidebar и AdminLayout.

### Архитектура и паттерны проектирования

**Feature-Sliced Design (FSD)** — архитектурная методология организации фронтенд-проектов, основанная на разделении кода на изолированные фича-модули. Каждый модуль инкапсулирует собственные компоненты, хуки, стили, типы и мок-данные. В проекте реализовано 15 фича-модулей в каталоге `src/ux/features/`.

**Component-driven development** — подход к разработке UI, при котором интерфейс строится из переиспользуемых компонентов-примитивов (UI-кит). В проекте 17 shared UI-компонентов в `src/ux/components/`.

**Barrel export** — паттерн реэкспорта модулей через единый файл `index.ts`, предоставляющий чистый публичный API каталога. Все 15 фича-модулей и инфраструктурные каталоги используют barrel exports.

**Mock-driven development** — подход, при котором каждый модуль содержит мок-данные (файлы `mock*.ts`), позволяющие вести разработку и тестирование UI автономно от серверной части. В проекте каждый фича-модуль включает файл мок-данных.

**Error Boundary** — паттерн React, реализуемый через class-компонент с методами `componentDidCatch` и `getDerivedStateFromError`. Перехватывает ошибки рендеринга дочерних компонентов и отображает fallback-UI вместо «белого экрана». В проекте реализован компонент ErrorBoundary в `src/ux/components/ErrorBoundary/`.

**Skeleton screen** — UI-паттерн индикации загрузки, при котором вместо спиннера отображается «скелет» страницы — серые прямоугольники, повторяющие форму будущего контента с shimmer-анимацией. Реализованы: ShimmerBlock, PaymentSkeleton, DashboardSkeleton, TableSkeleton, ProfileSkeleton, CatalogSkeletonCard.

### React-специфичные термины

**UI-кит (UI Kit)** — набор переиспользуемых UI-компонентов (кнопки, инпуты, модальные окна, вкладки, пагинация), образующих визуальную основу приложения. В проекте — 17 shared-компонентов в `src/ux/components/`.

**Компонент (Component)** — автономный, переиспользуемый блок пользовательского интерфейса в React. Принимает входные параметры (props) и возвращает JSX-описание своего отображения. В проекте 139 React-компонентов (*.tsx).

**Хук (Hook)** — функция в React (начинающаяся с `use`), предоставляющая доступ к состоянию, побочным эффектам и другим возможностям React из функциональных компонентов. В проекте: 5 инфраструктурных хуков (usePagination, useSortable, useInfiniteScroll, useFocusTrap, useScrollToTop) и ~25 фича-хуков.

**Контекст (Context)** — механизм React для передачи данных через дерево компонентов без явного пробрасывания props на каждом уровне вложенности. В проекте реализован ThemeContext для управления темой (light/dark).

**forwardRef** — API React, позволяющий передавать ref (ссылку на DOM-элемент) дочернему компоненту. В проекте используется в компоненте AppInput для доступа к DOM-элементу `<input>`.

### Тестирование

**Unit-тестирование (модульное тестирование)** — вид тестирования, при котором проверяется корректность работы отдельных изолированных модулей (функций, компонентов, хуков). В проекте проведено 176 unit-тестов.

**Vitest** — фреймворк для тестирования JavaScript/TypeScript-проектов, совместимый с API Jest. Обеспечивает высокую скорость выполнения за счёт использования Vite. В проекте используется Vitest 4.1.6.

**Testing Library** — семейство библиотек для тестирования UI-компонентов, ориентированных на тестирование поведения, а не деталей реализации. В проекте используются @testing-library/react 16.3.2, @testing-library/jest-dom 6.9.1, @testing-library/user-event 14.6.1.

**jsdom** — JavaScript-реализация стандартов DOM и HTML для использования в среде Node.js. Позволяет рендерить React-компоненты в тестовом окружении без браузера. В проекте используется jsdom 29.1.1.

**MSW (Mock Service Worker)** — библиотека для перехвата сетевых запросов на уровне Service Worker и подмены ответов мок-данными. В проекте используется MSW 2.13.0 для мокирования API при разработке и тестировании.

### Браузерные API

**IntersectionObserver** — API браузера, позволяющее асинхронно отслеживать пересечение элемента с областью видимости (viewport) или другим элементом. В проекте используется в хуке useInfiniteScroll для реализации бесконечной прокрутки каталога.

**Focus Trap (ловушка фокуса)** — паттерн доступности, при котором фокус клавиатуры зацикливается внутри модального окна: нажатие Tab на последнем элементе переводит фокус на первый, а Shift+Tab на первом — на последний. Реализован в хуке useFocusTrap.

**localStorage** — API браузера для хранения данных в виде пар «ключ-значение» без срока истечения. В проекте используется для персистенции выбранной темы (ключ `arendai-theme`).

**prefers-color-scheme** — медиа-запрос CSS, определяющий системные настройки пользователя относительно предпочтительной цветовой схемы (light или dark). В проекте используется в ThemeContext для автоопределения начальной темы.

### Внешние сервисы

**ЮKassa (YooKassa)** — российский платёжный шлюз для приёма онлайн-платежей. Поддерживает банковские карты, электронные кошельки, SBP и другие способы оплаты. В проекте интегрирован для обработки платежей за аренду; UI отображает 6 статусов транзакции (PENDING, AUTHORIZED, CAPTURED, CANCELED, REFUNDED, ERROR).

**Presigned URL** — временная подписанная ссылка, предоставляющая ограниченный по времени доступ к объекту в облачном хранилище (S3) без необходимости передачи учётных данных клиенту. В проекте используется для безопасной загрузки фотографий объявлений в Amazon S3.

**Amazon S3 (Simple Storage Service)** — облачное объектное хранилище от Amazon Web Services. В проекте используется для хранения фотографий объявлений, загружаемых пользователями.

### Предметная область

**P2P-платформа (Peer-to-Peer)** — платформа, обеспечивающая прямое взаимодействие между равноправными участниками (физическими лицами) без посредников. В контексте проекта — платформа аренды вещей между частными лицами.

**Аренда** — временное возмездное пользование вещью на основании договорённости между арендодателем и арендатором. Платформа «Арендай» обеспечивает весь цикл: от размещения объявления до взаимного оценивания.

**Бронирование (запрос на аренду)** — заявка арендатора на временное пользование вещью с указанием периода аренды. В системе создаётся сделка со статусом «Ожидает подтверждения» (PENDING).

**Сделка (Deal)** — центральная сущность платформы, отражающая процесс аренды от момента подачи заявки до завершения. Проходит через 7 статусов: PENDING → CONFIRMED → AWAITING_PAYMENT → ACTIVE → COMPLETED / REJECTED / CANCELLED.

**Модерация** — процесс проверки содержимого объявлений модератором платформы перед публикацией в каталоге. Включает оценку корректности описания, качества фотографий, отсутствия запрещённых товаров.

**Сервисный сбор** — комиссия платформы в размере 10 % от стоимости аренды, взимаемая с арендодателя при проведении платежа. Рассчитывается автоматически системой.
