## 1. О проекте

P2P-платформа аренды вещей между частными лицами «Арендай».

**Участники:**
- **Арендодатель** — регистрируется, создаёт карточку вещи (категория, описание, стоимость, залог, правила). Объявление идёт на проверку. Управляет объявлениями (изменяет/архивирует). Подтверждает/отклоняет бронирования. Уточняет детали через чат.
- **Арендатор** — ищет вещи в каталоге (фильтры: категория, цена, местоположение, доступность). В карточке: описание, фото, условия, рейтинг/отзывы владельца. Отправляет запрос на аренду (период + комментарий). Общается через чат, отслеживает статус.
- **Админ/Модератор** — проверяет объявления до/после публикации, отклоняет/блокирует, ограничивает доступ при нарушениях.

**Стек:** Next.js App Router, SCSS Modules, Framer Motion, Lucide icons, clsx. Все компоненты 'use client'. Русскоязычный UI.

### Границы проекта

**В скоупе:**
- Регистрация, аутентификация, персонализация профилей
- Полный цикл жизни объявления (создание → загрузка медиа → архивация), поиск, фильтрация, календарь доступности, избранное
- Бронирование, управление жизненным циклом через статусы, чат
- Двустороннее оценивание, рейтинг, отзывы
- Логирование действий, жалобы, модерация

**Вне скоупа:**
- Логистика (курьерские службы, физическая доставка)
- Юридика и страхование
- B2B-сегмент (только частные лица)
- ML-рекомендации и сложная аналитика
- Складское хранение и сервисное обслуживание

### Бизнес-требования
1. Регистрация (email/телефон + пароль), аутентификация, профиль, разграничение ролей
2. Создание объявлений (название, описание, характеристики, категория, стоимость, залог, ≥1 фото). Публикация только после модерации. При отклонении — редактирование и повторная подача
3. Поиск по ключевым словам, фильтрация (категория, цена, местоположение). В карточке: рейтинг/отзывы владельца, описание, фото, условия
4. Запрос на аренду с периодом → статус «ожидает подтверждения». Владелец подтверждает→«подтверждена» / отклоняет→«отклонён». После оплаты и обоюдного старта→«активна». После подтверждения возврата обеими сторонами→«завершена». Хранение истории всех запросов
5. Чат привязан к объявлению. Сообщения: отправитель, время, текст. Нельзя редактировать/удалять
6. Уведомления: новые запросы, изменение статусов, новые сообщения
7. Отзыв только после завершённой сделки. Рейтинг = среднее всех оценок. Отображается в профиле и карточке объявления
8. Жалоба на объявление или пользователя с указанием причины. Модератор обрабатывает. Логирование действий
9. НЕ логистика, НЕ юридическое сопровождение. Интеграция с внешними платёжными сервисами (без собственной платёжной системы)
10. Сервисный сбор 10% с арендодателя при проведении платежа (автоматический расчёт)

## 2. Команда и разделение ответственности

## 8. Диаграммы состояний (4 сущности)

### Объявление (6 состояний)
Черновик → Модерация → Активна → Архив → Удалено [конечное]
Модерация → Отклонена → Черновик (пересоздание)
Архив → Черновик (восстановление)

**Описания состояний:**
1. **Черновик** — начальное. Не видно другим. Можно редактировать, добавлять фото, настраивать календарь доступности. Часть полей необязательна.
2. **Модерация** — проверка модератором: корректность описания, качество фотографий, отсутствие запрещённых товаров.
3. **Активна** — опубликовано в каталоге, участвует в поиске, просмотре и формировании запросов на аренду.
4. **Отклонена** — с указанием причины (некорректное описание, нарушение правил, недостаточность данных). Можно доработать и повторно отправить на проверку.
5. **Архив** — снято с публикации, не в каталоге. Можно восстановить → Черновик.
6. **Удалено** — конечное, необратимое.

**Обязательные поля для модерации:** категория, заголовок, город, место передачи (pickup), цена, фото (≥1)

### Сделка аренды (7 состояний)
1. **Ожидает подтверждения** — начальное, заявка ожидает решения владельца объявления.
2. **Подтверждена** — владелец подтвердил. Все остальные заявки на те же даты автоматически отклоняются. Сделка готова к созданию платежа, но счёт ещё не выставлен.
3. **Ожидает оплаты** — создан счёт на оплату. Арендатор платит картой. После успешной оплаты деньги замораживаются на карте арендатора. Обе стороны должны подтвердить начало аренды (нажать «Старт»), после чего сделка перейдёт в активную фазу. Если оплата не поступает, любая сторона может отменить сделку.
4. **Активна** — после оплаты и двустороннего подтверждения старта. Объект аренды считается переданным во временное пользование. Досрочная отмена: частичный возврат пропорционально использованным дням.
5. **Завершена** — обе стороны подтвердили завершение. Товар в порядке → аренда владельцу, залог арендатору. Товар повреждён → аренда+залог владельцу. Просрочка >3ч → автозавершение, залог удерживается (штраф). После — можно оставить отзывы.
6. **Отклонена** — отмена сделки одной из сторон. Если на этапе ожидания подтверждения, подтверждения или ожидания оплаты — финансы не затрагиваются. Если в активной фазе — частичный возврат: арендатор платит за фактические дни, остаток и залог возвращаются.
7. **Отменена** — отмена сделки одной из сторон до завершения. Отмена может быть выполнена на этапах ожидания подтверждения, ожидания оплаты или активной аренды с возвратом.

**3 конечных:** Отклонена, Завершена, Отменена.

### Жалоба (4 состояния)
1. **Открыта** — пользователь подал жалобу (на пользователя или объявление) с указанием причины.
2. **В обработке** — модератор принял, анализирует причину, данные, историю, переписку.
3. **Решена** — нарушение подтверждено, модератор может инициировать дальнейшие действия (конечное).
4. **Отклонена** — жалоба не подтвердилась (конечное).

### Транзакция (6 состояний, ЮKassa)
1. **Ожидает** — начальное, счёт выставлен, оплата не произведена. Если не оплачена в срок — может быть отменена.
2. **Заморожена** — арендатор оплатил, деньги списаны с карты и удерживаются на счёте ЮKassa.
3. **Списана** — деньги переведены владельцу (конечное).
4. **Возвращена** — деньги возвращены арендатору при отмене сделки или условиях возврата (конечное).
5. **Ошибка** — сбой при оплате (Ожидает→Ошибка) или при списании (Заморожена→Ошибка). Возможна повторная обработка.
6. **Отменена** — отмена до успешной оплаты (конечное).

### Ключевые сценарии (подробно)

**Регистрация:** Открывает страницу → вводит данные → система проверяет → при ошибках — валидация → отправляет → система создаёт → автоматическая авторизация + редирект

**Поиск и выбор:** Каталог → параметры поиска → система фильтрует → карточка → описание, стоимость, календарь, рейтинг владельца, условия

**Отправка запроса:** Кнопка создания → период на календаре → проверка → отправка → «ожидает подтверждения»

**Прохождение аренды (арендатор):** Раздел сделок → «ожидает подтверждения» → арендодатель подтверждает → «подтверждена» + оплата → ЮKassa → «ожидает оплаты» → обоюдный старт → «активна» → обоюдное завершение → «завершена» → отзыв

**Обработка сделки (арендодатель):** Вкладка «сдаёт» → заявка → детали → подтвердить/отклонить → ожидание оплаты → обоюдный старт → «в аренде» → обоюдное завершение → «завершена» → отзыв

## 13. Диаграммы деятельности

### Создание объявления (3 дорожки: Пользователь | Система | Модератор)
1. Авторизация → «Создать объявление»
2. Заполняет: Категория, Заголовок, Цена, Залог
3. Загружает фотографии → «Сохранить» → DRAFT
4. Отправить на модерацию? Нет → DRAFT. Да → проверка полей
5. Система проверяет обязательные поля → MODERATION
6. Модератор → соответствует? Да → ACTIVE. Нет → REJECTED + причина
7. Пользователь исправляет → повторная отправка
8. Архивация → ARCHIVED. Восстановление → DRAFT

### Процесс аренды (3 дорожки: Арендатор | Система | Владелец)
1. Поиск → карточка → календарь → даты доступны? → «Арендовать»
2. Система проверяет активность, пересечения, календарь → «Ожидает подтверждения»
3. Владелец подтверждает/отклоняет
4. Подтверждена → система отклоняет конфликтующие → счёт (Ожидает оплаты)
5. Оплата → деньги заморожены → обоюдный старт → Активна
6. Обоюдное завершение → товар в порядке? → распределение средств → Завершена
