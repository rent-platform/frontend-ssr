## Общие правила

- Каждая сессия = **новый чат** (чтобы не терять качество из-за длинного контекста)
- В каждом чате ссылайся на файл: `@PROMPT_VKR_REPORT.md`
- Контекст проекта уже в памяти AI — он подтянется автоматически
- Формат вывода: **готовый текст для Word** на русском, академический стиль, без воды
- После каждой сессии копируй результат в Word-документ

## ⚠️ КРИТИЧЕСКИ ВАЖНО: Требования к стилю и объёму

**Каждый ответ — это готовый фрагмент текста для выпускной квалификационной работы (ВКР).** AI должен писать так, как будто он является автором раздела дипломной работы. Соблюдай следующие требования неукоснительно:

### Академический стиль
- Пиши **от третьего лица** или в безличной форме: «было реализовано», «разработан компонент», «в рамках данного модуля осуществляется»
- **Никаких** разговорных конструкций, сленга, маркетинговых формулировок
- Используй **научно-техническую терминологию**: «программный модуль», «пользовательский интерфейс», «архитектурный паттерн», «механизм валидации»
- Каждый абзац должен содержать **конкретику**: имена файлов, компоненты, количественные показатели, технические детали
- Избегай общих фраз вида «используются современные технологии» — вместо этого укажи **какие именно, зачем и как**

### Максимальная детализация
- **Не экономь на объёме.** Каждый раздел должен быть раскрыт максимально подробно — это ВКР, а не README
- Для каждого компонента/модуля/файла указывай: **назначение**, **что реализовано** (функциональность, логика, состояния), **внутреннюю структуру** (вложенные компоненты, хуки, стили), **связи** (от каких модулей зависит, что импортирует, что экспортирует)
- Включай **таблицы** везде, где это уместно: сводные таблицы компонентов, таблицы пропсов, таблицы статусов, таблицы маршрутов
- Описывай **паттерны проектирования** и **архитектурные решения** с обоснованием: почему выбран именно этот подход
- Для каждого хука — входные параметры, возвращаемые значения, побочные эффекты
- Для каждого SCSS-файла — какие визуальные элементы стилизует, какие миксины/переменные использует

### Формат для Word
- Структурируй текст с заголовками H2/H3/H4 для удобного переноса в Word
- Используй **нумерованные и маркированные списки** для перечислений
- Таблицы оформляй в Markdown-формате (легко конвертируется в Word)
- Листинги кода — в блоках ```code``` с указанием языка
- После каждого крупного раздела — **краткий вывод** (1–2 предложения), подытоживающий описанное

### Объём
- Минимально допустимый объём ответа на сессию: **3000–5000 слов**. Если раздел позволяет — пиши больше
- Лучше написать избыточно подробно (можно сократить при вставке в Word), чем поверхностно
- Если контекстное окно ограничивает — раздели ответ на части и укажи «продолжение следует», чтобы пользователь запросил продолжение
